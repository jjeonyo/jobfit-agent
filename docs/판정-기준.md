# 판정 기준 (평가셋 정답 라벨 작성용)

평가셋 정답 라벨(`eval/cases/*.json`)을 직접 작성할 때 쓰는 기준이다.
Matcher 프롬프트도 같은 기준으로 판정한다. 아래 "판정 정의"와 "고정 규칙"의 문장은
`app/agents.py`의 `VERDICT_RULES`와 글자 그대로 같아야 한다 (`tests/test_logic.py`가
확인한다). 기준을 바꾸면 두 곳을 함께 고치고, 이미 단 라벨을 다시 맞춘다.

## 판정 정의

- 매칭: 이력서 원문에 요건을 직접 충족하는 경험·기술이 적혀 있다.
- 부분 매칭: 관련 경험은 원문에 있으나 요건의 범위·수준·기간 중 일부만 충족한다.
- 없음: 원문에 근거가 없다.

'매칭'과 '부분 매칭'에는 근거 청크 id 인용이 필수다. '없음'은 인용을 비운다.

## 고정 규칙

- 매칭과 부분 매칭 사이에서 판단이 갈리면 부분 매칭으로 한다.
- 부분 매칭과 없음 사이에서 판단이 갈리면, 원문에 인용할 문장이 있을 때만 부분 매칭이고 없으면 없음이다.
- 인용할 문장이 없으면 없음이다. 추론은 근거가 아니다.
- 이력서에 '학습 중'으로 표기된 기술은 경험이 아니므로 경험 요건에 대해 없음으로 판정한다.
- 팀 작업은 원문에 적힌 담당 범위만 근거로 쓰고, 단독 경험으로 쓰지 않는다.
- 근무지·고용 형태처럼 이력서로 판단할 수 없는 조건은 근거가 없으므로 없음으로 판정한다.

보충:
- 추론 예: "FastAPI를 썼으니 비동기도 알 것이다"는 근거가 아니다.
- 학습 중 예: 이력서의 "학습 중 (실무 경험으로 표기하지 않음): Airflow, 클라우드, CI/CD".
- 근무조건의 '없음'은 '불충족'이 아니라 '이력서로 판단할 근거가 없음'이다.

## 라벨 작성 절차

1. 공고 원문을 `posting_text`에 붙여넣는다 (크롤링하지 않는다).
2. 요건을 직접 뽑아 `gold_requirements`에 적는다. 회사 소개·복리후생 문구는 요건이 아니다.
   `text`는 공고 문구를 그대로 옮긴다. 예측 요건과 id가 아니라 문장 유사도로 대응시키므로,
   요약·의역하면 대응이 안 될 수 있다.
3. 요건마다 위 기준으로 `verdict`(매칭/부분 매칭/없음)와 `citations`(근거 청크 id)를 적는다.
   청크 id는 `GET /chunks`로 확인한다. 판정을 아직 정하지 못한 요건은 `verdict`를 빼면
   판정 지표에서 제외된다.
4. 판단이 갈린 요건은 아래 "판정 사례"에 한 줄로 남긴다.

주의: 청크 id는 `data/profile.md`를 1,000자/중첩 100자로 나눈 순번이다. 이력서를 고치면
청크 경계가 바뀌므로, 정답 `citations`를 다시 확인해야 한다.
